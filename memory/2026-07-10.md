## 研究成果

### 关键差异点（必须桥接）

| 维度 | sqlvec-db | graphvec-db | 联邦策略 |
|------|-----------|-------------|----------|
| **一致性模型** | Raft共识（强一致） | Multi-Leader（最终一致性） | 统一 IConsensusAdapter 桥接 |
| **HLC实现** | 自定义 HLC 类 wall+logical+nodeId | @consento/hlc 封装 Uint8Array | 统一 IHLCRuntime 抽象 |
| **Outbox模式** | OutboxManager with LMDB (7 DBs) | OutboxReplicationManager | 统一 IOutbox 抽象 |
| **CDC** | PostgreSQL逻辑复制模型 | CDC consumer + adapter | 统一 ICDCManager 抽象 |
| **传输层** | RaftTcpTransport (mTLS) | ZMQ CURVE | 统一 ITransport 抽象 |
| **冲突解决** | LWWConflictResolver | resolveConflict() LWW/merge | 统一 IConflictResolver 抽象 |
| **反熵** | MerkleTreeSync | delta-sync | 统一 IAntiEntropy 抽象 |
| **分区处理** | Outbox freeze via ConsensusProvider | onMajorityChange callback | 统一被联邦层管理 |
| **共识接口** | IConsensusLayer (RaflessConsensus null-object) | ConsensusProvider (onMajorityChange) | 适配层适配器模式 |

### 产出文件

### 核心设计决策
1. **IFederationManager** 作为顶层编排器（新增，原有骨架缺失），负责整合复制/CDC/反熵/健康监控
2. **IFederationConsumer** 适配器接口，sqlvec-db 和 graphvec-db 通过各自消费者适配器接入联邦
3. 4层架构：Federation API → Core Services (Outbox/HLC/Conflict/Dedup/Topology) → Transport → Consensus
4. 传输层三重实现：TCPSecureTransport (mTLS) + ZeroMQTransport (CURVE) + InProcessTransport (测试)
5. 拓扑感知退避：intra-DC 3s / cross-DC 60s / edge 300s（与graphvec-db一致）
6. 因果一致性通过 HLC + compare/observe 机制保证
7. 零数据丢失通过 Outbox-before-send + WAL-anchored commit index + at-least-once delivery 保证
